# Agent Note: 产品选择的原生授权

Status: implemented

[English](2026-11-10-native-product-authorization.md) | 中文

## 问题

企业账号及其按组织隔离的凭据不能共用 DeepSeek 账号提供者的身份或登录状态。将登录页托管在渲染进程还会让授权回调进入应用渲染进程，并把第三方浏览器状态与工作区混合。

## 决策

产品层安装 `native-authorization` 并注册一个身份提供者。中性定义负责选择、安全组织选项及状态；企业提供者负责协议请求、验证、凭据存储、尝试代际与迟到结果拒绝。没有提供者时保留标准 DeepSeek Welcome。Main 不包含企业签发服务或组织分支。

Desktop Host 通过私有 Node IPC 桥接调用提供者。Main 和 Host 验证请求及响应字段，关联数值请求 ID，并在失败时返回固定诊断文本。Host 转发中性的 `native-authorization/changed` 事件，不导入业务身份服务。渲染进程 IPC 仅接受组织选择、有限视图几何及尝试取消或轮询，没有完成回调的操作。授权 URL 及拦截的授权码仅经过 Host/Main IPC。桥接在请求取消时中止在途工作，显式取消已经返回的所属尝试，取消撤销后迟到的成功 start 响应，并在退出时等待其拥有的全部工作结束。渲染进程不能通过保留旧尝试 ID 恢复授权。


Desktop Host 协议第 5 代要求支持私有原生授权状态及控制交换，包括标准产品的 null 状态。发行元数据会拒绝第 4 代，避免缓存的旧 Host 因不支持该请求而一直等待。
Main 仅接受已挂接窗口的精确主框架，每次尝试都创建全新的非持久 `WebContentsView` 会话。载体启用沙箱与上下文隔离，没有 Node 集成、预载、webview 或开发工具，并拒绝权限、新窗口及下载。导航只允许经过验证的 HTTPS 源。回调拦截还检查精确路径和固定查询值，拒绝重复 nonce，并且不会在载体中加载不匹配的回调。完成操作是带中止信号的私有闭包。窗口关闭、主框架替换、渲染进程失败、取消、尝试替换、更新移交及退出都会撤销载体。清理销毁文档、关闭连接，并等待存储、缓存及 HTTP 认证删除；清理失败仍由 shell 生命周期拥有者观察。每次终态读取都经过相同的结束路径，包括过期轮询被拒绝后的状态读取，防止旧二维码文档留在恢复后的入口上方。

Welcome 根据安全提供者状态选择页面。Host 会话丢失通知将已进入的工作区返回 Welcome。已验证的回调或 handoff 允许进入工作区，不把企业身份写入 DeepSeek 账号服务。即使原生浏览器或进程失败，提供者的取消和凭据代际检查仍具有最终效力。

## 考虑的替代方案

扩展 DeepSeek 账号联合类型会耦合独立凭据和业务协议。复用通用文本提示会隐藏原生浏览器生命周期及回调拥有者。渲染进程 iframe 或持久浏览器分区会暴露回调导航，或在尝试之间保留认证。业务专用 Main 分支会迫使每个新产品修改 shell。中性私有提供者与 Host 桥接保留产品选择，并使各身份提供者继续负责自身的凭据提交。

## 后果

针对性测试覆盖中性注册表、Main 控制器及原生载体的每条语句、分支和函数，包括迟到 start 响应、回调重放、所属窗口撤销及清理失败。真实 profile 组合在无需员工凭据的情况下验证四个已配置组织选项。生产组件浏览器夹具检查本地化控件、明暗主题、等待及过期状态和受限几何；这些夹具不证明真实员工授权通过。Linux Electron 冒烟使用内存 HTTPS 签发页，通过真实沙箱载体执行生产实现：验证无 Node 全局对象、不同临时会话、Cookie 与 localStorage 删除、私有回调拦截及所属窗口强制销毁。提前捕获所属 WebContents 引用，使 BrowserWindow 取值器失效后仍能完成清理。

真实企业登录完成需要员工企微设备及对应组织的在线回调。Windows x64 和 Mac ARM 原生行为、安装包签名、公证及签名更新验收需要相应平台机器与签名 CI。Linux 浏览器或 Electron 证据不能代替这些发行检查；这些测试不记录签名发行验收结果。
