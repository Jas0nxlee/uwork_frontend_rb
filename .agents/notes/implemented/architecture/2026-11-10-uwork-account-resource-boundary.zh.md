# Agent Note: UWork 账户资源与显式密钥创建

Status: implemented

[English](2026-11-10-uwork-account-resource-boundary.md) | 中文

## 问题

企业工作台需要账户、组织和受管模型状态，但不应接收凭据或重复原生资源缓存。设置页保持挂载时，其他窗口可能退出或更换当前 Host。服务器创建密钥后的网络故障不能导致第二次隐式创建请求。

## 决策

[ui-uwork-enterprise](../../../../packages/client/ui-uwork-enterprise/README.zh.md) 将安全的生成式 Remote 观察值发布到原生 Client resources，并通过 `useResource` 消费。账户 provider 跟随 `watchState`，组织名称来自公开配置。资源地址包含原生连接代次，因此断线或 Host 更换立即选择新的 source，重新连接时开启新的权威流。模型地址还包含当前已验证身份代次，使已退出或验证失败的账户不能保留已认证模型面板。

私有快照 store 只包含 mutation 交互事实：退出的等待与失败，以及密钥创建的等待与未知结果。它不包含凭据、账户投影、模型目录、读取缓存或轮询循环。资源模型负责共享、取消和过期帧拒绝。

自动模型读取使用不会创建密钥的安全刷新方法。创建受管密钥必须先打开说明服务端操作的独立弹窗，再点击确认按钮。未知响应会阻止再次创建。模型资源地址包含已完成操作的序号，强制开启新读取；只有同一 owner 的就绪或能力待补充观察值才能结算该交互结果。资源命令链在读取后验证当前安全身份与连接，旧 holder 不能清除结果。Host 在重启后继续保留持久化对账意图。成功读取会列出已发布模型，仅在 Host 明确报告缺少默认模型时要求用户选择。

## 考虑过的替代方案

- 带有第二套读取缓存的账户 controller 会重复标准 resources 层，并使失效处理更复杂。
- 不同 Host 代次保持相同资源地址，会在断线时保留旧账户详情。
- 把刷新或重连视为创建密钥的许可，会将读取变为服务端 mutation，并带来重复 POST 风险。

## 影响

Renderer 只接收安全身份与模型投影。跨窗口退出会移除账户专属操作及受管模型内容。读取失败后保留的详情会明确标为过期，且不能启用账户 mutation。原生 Main 负责返回登录窗口；此设置页不包含嵌入授权浏览器或回调处理器。
