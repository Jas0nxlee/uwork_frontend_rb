# Agent Note: UWork 受管模型权限与事务恢复

Status: implemented

[English](2026-11-10-uwork-managed-model-authority.md) | 中文

## 问题

企业模型路由跨越凭据、profile 设置、当前身份、模型能力与默认选择。这些存储没有共享事务。崩溃可能留下无凭据的路由，或已失去授权的凭据。创建密钥的失败响应无法证明服务端是否已创建。复用个人凭据名称、发现更多模型或覆盖并发保存的个人默认，会把恢复变成权限扩张。

## 决策

[uwork-model-provisioning](../../../../packages/llm/uwork-model-provisioning/README.zh.md) 拥有 Host 事务。凭据日志绑定组织、用户、代次、新 provider id 与新凭据引用。设置仅含引用和显式原生 pi-ai 模型声明；密钥留在凭据提供方。暂存日志先于密钥和设置版本写入。只有日志标为已提交才开放请求。失败补偿匹配的自有值；启动时删除旧路由和凭据，不把持久化材料视为已认证。恢复精确比较自有原始 profile，包括显示名和推理字段，避免 schema 默认值掩盖用户修改。设置变更仅触及自有 provider 路径。

推理通过同步 `llm-pi-ai/request-signal` waterfall 在解析凭据前授权。它核对精确端点、当前原始 profile 与已授权模型，并组合身份生命周期与调用方取消。退出和账号切换立即停止接收请求并取消在途推理。`llm-pi-ai/discovery-signal` 在已存或临时密钥发往修改过的端点前拒绝受管原生模型发现；能力读取改走绑定身份代次的网关客户端与显式发行 origin 白名单。个人发现继续通过 `next()`。

只有端点完整能力事实与显式账号授权的交集可供选择。明确的无限制授权允许已验证端点目录；缺失或发现失败不会扩大权限。模型名称不能证明 token 限制、工具、图像或推理能力。缺少事实时返回 `capabilities-required`。发行 `preferredModels` 顺序与可选模型取交集；空顺序要求选择。个人默认与 Session 选择保留。同账号受管默认可经 `agentDefaultModel.saveSelection(next, expected)` 更新；比较在 profile 写锁内执行，保留并发保存的个人选择。

创建密钥必须走独立显式 Remote 动作，并附上确认时保存的组织、用户与代次。Host 在实际身份回调内比较该快照，再构造网关客户端或允许 POST；晚到的确认不能为替换后的账号创建密钥。单次 POST 前，在按账号持久化的凭据 intent 中写入新别名。未知结果和崩溃留下的 pending 记录仅允许列表读取和别名核对，不能隐式再 POST。创建准入和所有完成写入都在凭据记录锁内比较所有权，旧响应不能覆盖新别名。已知发生在 POST 前的取消会补偿 intent。[账号资源决策](2026-11-10-uwork-account-resource-boundary.zh.md) 独立拥有 Renderer 观察与交互状态；仅安全状态 DTO 跨越 Remote。

## 考虑过的替代方案

**另建 LLM 传输。** 会重复原生流式、工具、附件和 Session 回放。受管路由改用 pi-ai。

**个人或环境密钥。** 复用个人默认密钥或省略引用，可能静默使用企业账号之外的认证。

**持久化就绪。** 相信已存 ready 标记或退出时保留活动路由，会使持久化超越授权寿命。

**隐式重试或回退。** 重试未知 POST 或撤权后另选模型，会隐藏未决变更或改变用户显式选择。

**按名称判断能力。** 把目录名称视为证据，会通过网关别名继承无关上游限制或模态。

## 影响

`uwork-` provider 前缀保留给受管路由。用户改过的受管 profile 可在清理后保留供检查，但自有凭据被移除，旧路由无法派发请求。若匹配别名始终不可观察，未知密钥结果可能需要服务端核对。真实认证模型能力与推理仍属于部署证据；本地 mock 不能证明生产网关支持声明的模态。

包内测试覆盖各暂存阶段写后中断、重启补偿、设置和凭据竞争、别名所有权、精确端点准入、授权缩减、显式无限制授权和个人默认保护。真实 Loader profile 组合 credentials-local、settings、默认选择和原生 pi-ai；原生发现测试证明被拒绝的受管草稿既不解析已存凭据，也不发网络请求。第二个 profile runtime 验证条件默认写入能保留并发个人保存。
