# Agent Note: 通过不可变内容激活公司技能

Status: implemented

[English](2026-11-10-company-skill-activation.md) | 中文

## 问题

PUBLIC SkillHub 分发指令归档，现有插件管理器则安装可执行 npm bundle。混用两种载荷会给内容下载包安装权限，也会使更新失败破坏运行中任务引用的指令。取消或写入确认丢失还可能导致激活结果未知。

## 决策

[公司市场](../../../../packages/boot/uwork-company-market/README.zh.md)拥有独立内容存储。激活前校验准确的解析身份、跨平台归档路径、有界解压、发布复合指纹及原生指令解析。不可变版本在跨进程写锁内通过一次原子索引替换变为可见。技能读取使用原子索引快照，下载不会阻塞对活动版本的访问。索引保留此前已提交版本直到显式卸载；恢复只清理自有暂存和未引用候选。

写入确认失败后重新读取索引。结果不可读时保留候选，不展示为可信状态，也不假定已经回滚。技能发现复用原生文件系统 provider，公司根目录排在个人根目录之后；安装管理不修改个人技能或 npm bundle。

## 考虑过的替代方案

- 复用 npm 安装会执行另一种载荷协议，并与普通插件混用所有权。
- 原地替换技能目录会使运行中任务持有的路径失效，也增加中断恢复的复杂度。
- 每次写入报错都删除候选，会删除已提交但未确认索引所引用的内容。

## 影响

索引是激活状态的依据；持久状态损坏需要修复，不退回空存储。保留版本在卸载前占用可配置预算。原子替换不承诺断电持久性，内容完整性也不代表执行安全：工具继续受原生权限和审批约束。
